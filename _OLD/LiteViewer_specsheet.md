# LiteViewer — Windows軽量画像ビューア仕様書

- **文書版数**：v1.7（v1.0〜v1.7の仕様変更を統合）
- **更新日**：2026-10-11
- **位置づけ**：開発・検証の基準文書。実装状況は末尾に別記。
- **参考製品**：[MassiGra](http://www.massigra.net/)（操作性・軽量性を参考にするが、互換性・忠実な再現を保証するものではない）

## 1. 目的・基本方針

画像閲覧専用の軽量なWindowsネイティブアプリケーションを作る。主眼は速い起動、前後画像の軽快な切替、快適なズーム・パン、全画面閲覧、インストール不要のポータブル運用。画像編集、画像保存、スライドショー、漫画・見開き表示は行わない。

### 1.1 確定技術要件

| 項目 | 仕様 |
|---|---|
| 仮称 | LiteViewer |
| 言語 | C11 |
| GUI | Win32 API（User32/Comctl32など） |
| 描画 | GDI中心、透明画像の合成にはAlphaBlend |
| デコード | WIC（Windows Imaging Component） |
| 開発・ビルド | MSYS2 **UCRT64**、MinGW-w64 GCC、GNU Make、windres |
| 対象 | Windows 10/11、x86-64 |
| 配布 | インストーラ不要のEXEと任意のINI。Windows標準DLL以外の同梱を原則不要とする |
| 設定 | INIファイル＋最小限のWin32設定ダイアログ |
| 通信 | 不要。ネットワークへの自発的通信なし |
| 対象外 | 画像編集・保存・削除・移動・変換、スライドショー、漫画モード、サムネイルDB、外部プラグイン |

「Win32 APIのみ」はWindows標準COMであるWICを含む。MFC、ATL、.NET、Qt、SDL、外部デコードライブラリは使わない。

## 2. 表示設定（採用値・変更確定）

| 設定項目 | キー | 既定値 | 意味 |
|---|---|---|---|
| 初期倍率 | `Display.FitMode` | `ShrinkOnly`（UIではshrink） | 表示領域より大きい画像だけ全体縮小。小さい画像は100% |
| 背景色 | `Window.BackgroundColor` | `#202020`（UIではdark） | ダークグレー |
| 品質 | `Display.Interpolation` | `HighQuality`（UIではhigh） | 不透明画像はGDI `HALFTONE`を基本とする |
| ズーム固定 | `Display.ZoomLock` | `0` / false | 画像切替時に初期表示モードへ戻す |
| ループ | `Navigation.Loop` | `1` / true | 最後の次は先頭、先頭の前は最後 |

### 2.1 倍率・配置の規則

画像の表示向き補正後の幅高さを `Iw, Ih`、画像表示領域を `Vw, Vh` とする。

- **原寸**：`z = 1.0`
- **全体フィット**：`z = min(Vw/Iw, Vh/Ih)`
- **縮小のみフィット**：`z = min(1.0, Vw/Iw, Vh/Ih)`
- **幅フィット**：`z = Vw/Iw`
- **高さフィット**：`z = Vh/Ih`
- **手動ズーム**：1回ごとに1.25倍または1/1.25倍。手動操作の範囲は1%〜3200%。極端に巨大な画像の全体フィットは下限1%より小さくてもよい。
- **中央配置**：表示サイズが表示領域より小さい軸では中央へ配置する。
- **パン**：左ドラッグのみ。画像が大きい軸では空白が極力露出しない範囲に制限する。
- **カーソル位置ズーム**：Ctrl+ホイールで、カーソル直下の画像上の位置を可能な限り維持する。
- **ズーム固定OFF**：画像切替時は初期倍率へ戻す。固定ONでは倍率を引き継ぎ、パン位置は中央に戻す。
- **別フォルダを開く**：ズーム固定ONでも初期倍率を適用する。

## 3. ウィンドウ・画面

| 構成 | 要件 |
|---|---|
| 標準表示 | タイトルバー、メニュー、画像領域、ステータスバー |
| シンプル表示 | タイトルバーと画像領域、メニュー・ステータス非表示 |
| 全画面 | ボーダーレス、メニュー・ステータス非表示。表示解像度は変更しない |
| タイトル | `ファイル名 — LiteViewer` |
| ステータス | 表示位置/総数、画像解像度、倍率、画像形式 |
| ウィンドウ状態 | 位置・サイズ・最大化状態を保存・復元。全画面解除で元の状態へ戻す |
| DPI | Per-Monitor DPI Aware V2を目標。100%は画像1ピクセル＝1画面物理ピクセル |
| マルチモニタ | ウィンドウが最も重なるモニタへ全画面化 |
| コンテキストメニュー | 前/次、表示倍率、全画面、設定、終了など |

ツールバー、サムネイルペイン、フォルダツリーは設けない。

## 4. ファイルの読み込み・ナビゲーション

1. `Ctrl+O`のファイル選択、コマンドライン第1引数、Explorerからのドロップで画像を開く。
2. 指定画像が存在するフォルダ直下の対応ファイルを列挙する。サブフォルダは再帰走査しない。
3. フォルダをドロップした場合、直下の先頭画像を表示する。複数ファイルのドロップでは先頭だけ扱う。
4. ファイル一覧は自然順を既定とし、名前、更新日時、サイズの各昇順・降順に変更できる。同値のときは名前をタイブレークに使う。
5. `前/次`、`先頭/最後`で移動する。ループ初期値はON。
6. `F5`で一覧を再生成し現在画像を再読み込みする。フォルダ内容の自動監視は初期対象外。
7. Unicodeパス、UNCパス、長いパスを可能な範囲で扱う。ファイル名・パスの内部表現はUTF-16。
8. ファイルに読み取り失敗や形式不一致があっても異常終了せず、次の画像に移動できる。

### 4.1 画像形式

| 形式 | 対応 |
|---|---|
| JPEG (`jpg/jpeg/jpe`) | 標準対応、EXIF Orientation考慮 |
| PNG (`png`) | 標準対応、透過を維持 |
| BMP (`bmp/dib`) | 標準対応 |
| GIF (`gif`) | 先頭フレームのみ。アニメーション再生なし |
| TIFF (`tif/tiff`) | 先頭ページのみ |
| ICO (`ico`) | 先頭として選択されたフレームのみ |
| WebP (`webp`) | 利用可能なWICコーデックに依存 |
| HEIF (`heif/heic`) | 利用可能なWICコーデックに依存 |
| AVIF (`avif`) | 利用可能なWICコーデックに依存 |
| RAW、PSD、SVG、書庫内画像 | 標準では対応しない |

拡張子にかかわらず、WICが実際にデコードできなければエラーとする。

## 6. デコード・描画

- **処理経路**：ファイル → WICデコーダ → EXIF Orientation補正 → 32bpp PBGRA変換 → DIB/キャッシュ → GDI描画 → ウィンドウ。
- **内部画像形式**：32bpp Premultiplied BGRA、Top-down DIBを原則とする。
- **不透明画像**：`StretchBlt`、`COLORONCOLOR`（高速）または`HALFTONE`（高品質）。
- **透明画像**：`AlphaBlend`で背景と合成する。透過がある場合、高品質指定でもGDIの補間能力に依存する。
- **背景**：標準は単色`#202020`。市松模様表示は仕様上の追加表示オプション（実装対応状況は要検証）。
- **ダブルバッファ**：メモリDCとバックバッファに描画し、`WM_PAINT`で`BitBlt`転送。`WM_ERASEBKGND`によるちらつきを抑制。
- **表示倍率・パンの変更**：既存のデコード画像を再描画し、原則再デコードしない。
- **EXIF Orientation**：1〜8を表示上適用。タグがなく解析できなければ値1とする。元ファイルは変更しない。
- **GDI資源**：選択中ビットマップを削除する前に、`SelectObject`で元のビットマップを戻す。不存在の`DEFAULT_BITMAP`定数は使わない。

## 7. 非同期ロード・キャッシュ

| 項目 | 仕様 |
|---|---|
| UIスレッド | 入力・画面・GDI描画 |
| デコード用ワーカー | 原則1本。WIC/COMの初期化・解放を担当 |
| 優先順位 | 現在要求画像 → 次画像 → 前画像 |
| 先読み | 前後各1枚 |
| 最大キャッシュ | 初期値256MiB、LRUで追い出し |
| 現在画像 | キャッシュ容量制限とは別枠で表示を試行 |
| 単一画像の安全上限 | デコード画像バッファ概ね1GiB（仕様目標） |
| 状態 | `EMPTY` → `QUEUED` → `LOADING` → `READY` / `FAILED` |
| 連続送り | 最新の表示要求だけを描画対象にする。古い待ち要求は破棄 |
| 失敗時 | 原則エラーを表示し閲覧を継続。再試行は明示的な再読み込みで行う |

キャッシュはファイルパスで識別する。ファイル変更時の自動キャッシュ無効化はv1.7実装では未対応であり、`F5`で再読み込みする。

## 8. 設定管理

- 既定でEXEと同じディレクトリの`LiteViewer.ini`を読み込む。
- 設定ファイルがなければ内部既定値を使う。
- GUIの「OK」で設定を確定し、可能なら保存。書き込み失敗は通知する。
- アプリ独自の通常設定はレジストリに保存しない。
- INIはUTF-8（BOMなし）を標準とし、自前パーサーの採用を設計方針とする。
- 不明キー・不正な値は、利用できるほかの設定に影響させず既定値を使う。

### 8.1 確定済みINIの基本例

```ini
[General]
ConfigVersion=1

[Window]
Width=1024
Height=768
Mode=Normal
BackgroundColor=#202020
ShowStatusBar=1

[Display]
FitMode=ShrinkOnly
ZoomStep=1.25
ZoomLock=0
Interpolation=HighQuality
Transparency=Solid
AutoOrientation=1

[Navigation]
SortBy=NaturalName
Descending=0
Loop=1

[Cache]
MaxMemoryMB=256
```

※この例は当初のソースZIPに同梱したINIに合わせている。長期設計で検討した`ZoomMin`/`ZoomMax`、キー割り当て、`PreloadNext`/`PreloadPrevious`、市松模様設定などは、コード上の実装・保存互換性を確認してから拡張する。

### 8.2 設定GUI

Win32標準ダイアログで必要最小限を提供する。対象は初期倍率、背景、描画品質、ズーム固定、ループ。複雑なキー設定GUIは設けない。

## 9. メニュー構成とリソース分離（v1.5）

- **ファイル**：開く、再読み込み、画像をコピー、画像の情報、終了
- **表示**：原寸、縮小のみフィット、全体/幅/高さフィット、ズーム固定、シンプル、全画面
- **移動**：前、次、最初、最後、並べ替え
- **設定**：表示設定、設定ファイルを開く、既定値に戻す
- **ヘルプ**：操作一覧、バージョン情報

### 9.1 Win32リソース管理方針

メインメニュー、右クリックメニュー、設定ダイアログ、画像情報ダイアログ、アクセラレータ、アイコン、マニフェスト、固定文言（移行済みのもの）は `src/resource.rc` に定義する。IDは `include/resource.h` に集約する。画像情報ダイアログの表示値は `src/info.c` で設定し、CコードによるUIコントロールの動的配置を避ける。

- `IDR_MAINMENU`：メインメニュー
- `IDR_POPUPMENU`：右クリックメニュー
- `IDR_ACCELERATORS`：キーボードアクセラレータ
- `IDD_SETTINGS`：表示設定
- `IDD_IMAGEINFO`：画像情報
- `IDI_APP`：アプリアイコン
- `STRINGTABLE`：案内・エラー文言の一部

コントロールの選択肢や可変文字列など、なおC側に残るものは今後の追加分離対象とする。

## 10. アイコン仕様（v1.3追加）

「写真フレーム＋山・空・水辺」のモチーフで、画像ビューアを識別しやすい青系のアイコンを採用する。小さいサイズでも外枠と景色のシルエットが認識でき、ライト/ダーク背景の両方を想定する。

| 項目 | 内容 |
|---|---|
| 画像ファイル | `src/LiteViewer.ico` |
| 収録サイズ | 16、24、32、48、64、96、128、256px |
| リソースID | `101` |
| RC記述 | `101 ICON "src/LiteViewer.ico"` |
| ウィンドウ | `LoadImageW(instance, MAKEINTRESOURCEW(101), IMAGE_ICON, ...)`を使い大/小アイコン設定 |
| 表示先 | Explorer上のEXE、タスクバー、タイトルバー、Alt+Tabなど |
| 配布 | EXEに埋め込み、外部ICOは配布不要 |

`src/resource.rc`のマニフェストとアイコンを`windres`でオブジェクト化する。アイコン更新時はリソースも再ビルドする。

## 11. ビルド・配布仕様

### 11.1 MSYS2 UCRT64

```bash
pacman -S --needed \
  mingw-w64-ucrt-x86_64-gcc \
  mingw-w64-ucrt-x86_64-binutils \
  make

make clean
make
cp LiteViewer.ini dist/
```

生成先：`dist/LiteViewer.exe`。MSYSの`/usr/bin/gcc`ではなく、UCRT64の`/ucrt64/bin/gcc`を使う。

### 11.2 Makefileの主要オプション

```makefile
CFLAGS := -std=c11 -O2 -Wall -Wextra -Wno-unused-parameter -DUNICODE -D_UNICODE -DCOBJMACROS -D_WIN32_WINNT=0x0A00 -Iinclude
LDFLAGS := -municode -mwindows
LDLIBS := -luser32 -lgdi32 -lmsimg32 -lcomdlg32 -lcomctl32 -lshell32 -lshlwapi -lole32 -lwindowscodecs -luuid -lcomctl32 -lm
```

**重要**：エントリーポイントは`wWinMain`。`-mwindows`だけでは`undefined reference to WinMain`となり得るため、リンク時の`-municode`が必要（v1.2修正）。

## 13. エラー処理・保護

- 対応していない画像、破損、コーデック不在、読み取り不可は表示エラーとし、アプリ全体を停止しない。
- WICデコード前に幅・高さ・バッファサイズの積のオーバーフローを検出する。
- 大きすぎる画像やメモリ不足は安全に失敗させ、バッファ確保失敗を処理する。
- GDIオブジェクト、COMオブジェクト、スレッドハンドルを正しい順序で解放する。
- ワーカースレッドは終了通知と待機で停止し、`TerminateThread`は使わない。
- ファイルパスはUTF-16で扱い固定長`MAX_PATH`だけを前提としない。
- ネットワーク接続、画像編集、原画像更新は行わない。

## 14. 性能目標（保証値ではない）

| 指標 | 目標 |
|---|---|
| EXEサイズ | 目標1MiB以下、目安上限2MiB程度（アイコン内包により増加あり） |
| ウォーム起動 | 200ms以内を目標 |
| コールド起動 | 500ms以内を目標 |
| キャッシュ済み画像の切替 | 50ms以内を目標 |
| メモリ | キャッシュ上限256MiB初期値。現在画像、描画バッファ等は別枠 |
| 非同期 | 画像読込中も基本UIが応答すること |
| 配布 | 外部フレームワーク不要、通常起動に管理者権限不要 |

ストレージ、画像寸法、PC構成等で大きく変動するため、実測後に見直す。

### 16.1 機能仕様と実装の差分

## v1.4 追加仕様：クリップボードへの画像コピー

- **操作**：`Ctrl+C`、［ファイル → 画像をコピー］、画像上の右クリックメニュー。
- **対象**：現在表示中の画像データ。画像ファイルのパス、画面キャプチャー、表示倍率、パン状態はコピー対象外。
- **画素寸法**：デコード済みの原寸サイズ。EXIF Orientation適用後の方向で出力。
- **Windowsクリップボード形式**：`CF_DIB`、24bpp BGR、bottom-up、行は4バイト境界。一般的な画像貼り付け先との互換性を重視。
- **透過画素**：設定された単色背景色（既定 `#202020`）に合成し、アルファは保持しない。市松模様表示を選んでいても単色の設定背景色で合成する。
- **未読み込み・読込失敗**：コピー不可の案内を表示し、既存のクリップボード内容は保持する。
- **クリップボードが他プロセスに使用されている場合**：コピー失敗を通知。
- **メモリ所有権**：`GlobalAlloc(GMEM_MOVEABLE)`に格納したDIBを`SetClipboardData`に渡し、成功時はOSへ所有権移転。
- **画像編集・保存機能**：引き続き非対応。
- **実装版数**：ソース v1.4以降。MSYS2 UCRT64での実機ビルド・実機動作は未検証。


## v1.5 追加仕様：UIのWindowsリソースファイルへの切り離し

- **基本原則**：UIの構造、ラベル、メニューの階層、アクセラレータ、固定文字列は可能な限りRC定義に集約する。
- **リソース配置**：`src/resource.rc`、`src/LiteViewer.ico`、`src/manifest.xml`、`include/resource.h`。
- **ダイアログ生成**：`DialogBoxParamW` を用い、項目レイアウトは `DIALOGEX` で規定。Cのダイアログプロシージャでは値の入出力、検証、コマンド処理を担当する。
- **メニュー**：`MENU` リソースとして定義し、CではメニューIDを処理する。
- **ショートカット**：`ACCELERATORS` リソースと `TranslateAcceleratorW` に統一する。
- **ビルド**：`windres` でRCをCOFFオブジェクトへ変換し、EXEへリンクする。日本語RCのUTF-8エンコーディングに配慮する。
- **制約**：既存の動的UI文言が完全に外出しされているわけではなく、段階的に移行する。

## v1.6 変更仕様：画像ナビゲーションキー（確定）

| キー | 動作 | リソース内のコマンドID |
|---|---|---|
| `Left` / ← | 前の画像 | `IDM_PREV` |
| `Right` / → | 次の画像 | `IDM_NEXT` |
| `Up` / ↑ | 最初の画像 | `IDM_FIRST` |
| `Down` / ↓ | 最後の画像 | `IDM_LAST` |

`src/resource.rc` の `IDR_ACCELERATORS` に上記を定義する。方向キーによるパンは廃止し、パン操作はマウス左ドラッグのみとする。**旧割り当ての Space / Backspace / PageUp / PageDown / Home / End によるナビゲーションは廃止**する。ホイールでの前後移動は維持する。

## v1.7 追加仕様：画像情報ダイアログ

### 画面起動と配置

- 起動：`I` キー、［ファイル → 画像の情報］、右クリック →［画像の情報］。
- 構造：標準Win32モーダルダイアログ。`IDD_IMAGEINFO DIALOGEX` を `src/resource.rc` に定義する。
- ボタン：［OK］で閉じる。タイトルは `LiteViewer - 画像の情報`。
- 内容：読み取り専用のテキスト欄。元の画像を変更しない。
- 実装担当：`src/info.c`。現在のファイル一覧・画像キャッシュから情報を取得し、原則として再デコードしない。

### 表示項目（確定）

| 表示順 | 項目 | 内容・計算方法 |
|---|---|---|
| 1 | ファイル名 | 拡張子を含む名前 |
| 2 | ファイルの場所 | 所属フォルダ |
| 3 | フルパス | ファイルの絶対パス |
| 4 | ファイル形式 | JPEG、PNG、BMP、GIF、TIFF、ICO等（現実装は拡張子から識別） |
| 5 | 元のサイズ | デコード済み画像の幅 × 高さ（ピクセル）。Orientationが適用されたキャッシュ画像に基づく |
| 6 | 現在のサイズ | 画像寸法 × 現在倍率（ピクセル・倍率％）。原画像はリサイズしない |
| 7 | ディスク上のサイズ | ファイルのバイト数、KiB/MiB表示 |
| 8 | メモリ上のサイズ | キャッシュにある展開後の画像バイト数 |
| 9 | フォルダ内の順番 | 1始まりの現在位置 / 一覧件数 |
| 10 | ファイルの更新日時 | ローカル時刻 `YYYY/MM/DD HH:MM:SS` |

**表示しない項目**：解像度（DPI）、印刷サイズ、使用色数、読み込み時間。

画像が未ロード・ロード中の場合は、取得できない欄に「読み込み中」「取得できません」「—」等を表示する。ファイルが未選択の場合はダイアログを開かない。

### 注記

「現在のサイズ」は画面表示時の拡大縮小された見かけの画素寸法であり、ファイルの解像度・DPI情報や、ウィンドウに切り取られて見える範囲とは異なる。ファイル形式名は現在のコードでは主に拡張子に基づくため、実際の符号化形式と異なる可能性がある。
